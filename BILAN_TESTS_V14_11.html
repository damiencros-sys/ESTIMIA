ESTIM’IA V14.11

44 contrôles serveur réussis

  • Page de connexion accessible ; fichiers applicatifs et API refusés sans authentification.
  • Champs username et current-password adaptés au gestionnaire de mots de passe du navigateur. Aucun mot de passe renvoyé dans le HTML.
  • Identifiants erronés refusés, origine étrangère refusée, limitation des tentatives.
  • Cookie persistant de 30 jours : Secure, HttpOnly et SameSite=Lax ; identifiant, expiration et nonce signés, sans mot de passe dans le jeton.
  • Cookie de session simple sans Max-Age lorsque la case est décochée, validité serveur de 8 heures.
  • Connexion réutilisée dans un nouveau client avec le même cookie ; signature stable avec la même configuration serveur.
  • Jeton corrompu, expiré ou mal formé refusé. Changement d’identifiant ou mot de passe invalidant la signature.
  • Déconnexion : cookie effacé, puis accès aux fichiers applicatifs refusé.
  • Ancienne route /api/save toujours désactivée.

Limites

Le gestionnaire du navigateur décide s’il propose de mémoriser le mot de passe. ESTIM’IA mémorise la connexion via un cookie signé, pas un mot de passe en clair. Effacer les cookies ou utiliser la navigation privée peut interrompre la session. Le bouton de déconnexion efface le cookie local ; changer le mot de passe Render invalide toutes les connexions. Pas de révocation centralisée d’un jeton individuel.

HTTPS requis. Variables Render identiques à V14.10. Aucun déploiement distant, aucun test sur appareil Samsung physique. Aucun moteur d’analyse automatique des photos ajouté. Les vérifications de V14.10 restent celles de cette version antérieure ; elles ne sont pas présentées comme toutes réexécutées pour cette évolution de connexion.
